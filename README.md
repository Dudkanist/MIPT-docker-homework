# Bio-Gene Tracker API (Docker Assignment)

## Описание проекта
Данный проект представляет собой легковесное веб-приложение на базе **FastAPI**, предназначенное для отслеживания и хранения информации о генах. Приложение позволяет добавлять названия генов с их описанием и просматривать список всех сохраненных записей через интерактивную документацию Swagger или API-запросы.

## Выбранный вариант задания
Реализован **Вариант №3 («Данные не теряются»)**.
Этот вариант выбран для демонстрации навыков полной контейнеризации приложения, включая:
1.  Проброс портов для доступа к веб-интерфейсу извне.
2.  Использование переменных окружения (`ENV`) для гибкой настройки порта приложения.
3.  Настройку **Named Volumes** для обеспечения постоянного хранения данных (файла `genes.txt`) независимо от жизненного цикла контейнера.

## Технологический стек
* **Язык:** Python 3.11
* **Фреймворк:** FastAPI + Uvicorn
* **Базовый образ:** `python:3.11-slim` — выбран как специализированный и оптимизированный по размеру образ (в отличие от тяжеловесного Ubuntu), что соответствует критериям оценки.

## Инструкция по запуску

### 1. Подготовка и сборка

# Клонирование репозитория

git clone https://github.com/Dudkanist/MIPT-docker-homework.git

cd MIPT-docker-homework

# Сборка образа (используется lowercase имя согласно правилам Docker)

docker build -t mantsevich_docker .

### 2. Первый запуск и создание данных
Запускаем контейнер с пробросом порта и монтированием тома для данных:

docker run -d -p 8080:8080 -v bio-data:/app/data --name app mantsevich_docker


**Проверка:** 

* Откройте в браузере: http://localhost:8080/docs

* Используйте POST-запрос `/genes/`, чтобы добавить тестовый ген.

### 3. Демонстрация сохранности данных (Критерий Варианта 3)

Удаляем контейнер и запускаем его заново. Благодаря томам данные сохранятся:

# Полная остановка и удаление текущего контейнера

docker stop app && docker rm app

# Повторный запуск с тем же томом

docker run -d -p 8080:8080 -v bio-data:/app/data --name app mantsevich_docker


**Результат:** После перезапуска сделайте GET-запрос к `/genes/`. Вы увидите, что записи, созданные в пункте 2, остались на месте.


## Технические особенности реализации
* **Dockerfile:** Использует многостадийное копирование (сначала `requirements.txt`) для эффективного кэширования слоев.
* **.dockerignore:** Настроен на исключение системного мусора (`__pycache__`), локальных виртуальных окружений и папок с данными, что гарантирует «чистоту» образа.
* **Слушание интерфейса:** Приложение внутри контейнера слушает `0.0.0.0`, что делает его доступным снаружи через мост Docker.
* **Переменные окружения:** Порт приложения задается через `ENV APP_PORT=8000` в Dockerfile и считывается в `main.py`.
